# Review, 2026-10-27

Three independent adversarial reviews, one per layer: the contract, `genesis-rules`, and the two
service shells. Each reviewer was told to assume the author had missed something, and proved its
findings with tests. The registry is not deployed anywhere yet, so every fix below shipped before any
deployment.

## Contract (`contracts/src/SafeGenesisRegistry.sol`)

**The main claim held.** No input files a record under a real Safe's address with parameters that do
not deploy that Safe. The reviewer checked several properties and found them sound:

- the encoding has no ambiguity, and the proxy-code/singleton split is unique (fuzzed);
- the derivation matches the v1.0.0–v1.5.0 factory sources;
- `deployCallOf` deploys at the recorded address;
- writes are write-once and idempotent;
- the deployment address reproduces from an independent compile (no PUSH0, no metadata).

| Finding | Severity | Change |
| --- | --- | --- |
| A record does not prove the contract at `factory` is Safe's: a hostile factory can return the right proxy code and deploy the right address with its own setup | medium | NatSpec and README now separate what a record proves from what a replay must check: runtime code hashes of the factory and every dependency, then the deployed Safe's configuration |
| On a chain without the singleton, anyone can deploy a v1.0–v1.3 proxy uninitialized, and whoever calls `setup` first owns it | low | Documented as a hostile-party risk |
| A full 16 KiB record cost ~14M gas, close to EIP-7825's 16.78M cap | low | `MAX_INITIALIZER_LENGTH` is now 8 KiB (~7M gas); the deployment address changed accordingly |
| The text called this a "keccak256 collision"; for an undeployed Safe, a party choosing both parameter sets has a ~2^80 birthday search | info | Wording corrected; README tells wallets to fund an undeployed Safe only on parameters they generated themselves |
| The deterministic deployer is unavailable on some chains; `recordedAt` is the L1 block number on Arbitrum; `createProxyWithNonceL2` emits an extra event; `totalRecords` counts any record | info | Documented |
| Some tests restated the formula instead of calling a factory; fork tests counted reverts without failing; post-replay checks covered owners only | test gaps | Fuzzing now runs against a factory deployment. `RealSafesTest` fails on any revert it did not predict from the setup, and after each replay checks owners, threshold, fallback handler and guard. A full-size record is tested to fit in one transaction |

## Rules (`genesis-rules`)

**Critical: the replay check returned `ready` for setups that ran attacker code.** The reviewer proved
five such setups:

- SimulateTxAccessor used as a setup hook;
- a MultiSend 1.5.0 leg to address 0, which runs as the Safe itself;
- trailing fragments and over-long lengths, which MultiSend still executes;
- nesting deeper than the parser followed;
- unknown code reported as `unverified` instead of blocked.

The cause was the design, not a single bug. The known-contracts table said what code sits at an
address. It did not say which calls to that code are safe during setup.

**Change: the replay check is now default-deny** (`replay.rs`):

- Known contracts have kinds. Each role accepts only its kinds, so known code in the wrong role is
  blocked.
- A replay is `ready` only for a shape that is read completely and matches exactly:
  - no hook;
  - `SafeToL2Setup`;
  - `SafeModuleSetup.enableModules`;
  - or a MultiSend whose every leg is a known (kind, operation, function, canonical arguments)
    combination.
- MultiSend legs must consume every byte. A leg to address 0 is blocked. Nesting is blocked.
- Everything else is `blocked`. `unverified` now means only an owner the check cannot vouch for.
- Owners that are contracts are checked. One bound to its own genesis passes. One with different
  code on the target chain is blocked. One with nothing binding its address is `unverified`.
- The owners a Vela setup creates through the passkey signer factory are recognised. This is checked
  against all 184 real Vela wallets.
- `controlledBy` / `creates` is stated only for a `ready` replay.
- Drift now covers modules, fallback handler and guard (`authorityChanged`).

All of the reviewer's attacks are kept as a regression suite (`tests/attacks.rs`), and each is now
`blocked`.

| Finding | Severity | Change |
| --- | --- | --- |
| Transaction-service parameters that mismatch never fall back to the creating transaction | medium | `ServiceCreation::fallback` |
| Import lifecycle: a task left `Succeeded`-but-unrecorded waits forever; pre-broadcast failures never end; `admit` checked only in debug builds | medium | A time limit on every waiting branch; failures counted, and the task rotated to the back of the queue; real admission checks that mirror the contract's preconditions |
| A hostile 128 KiB calldata scan took seconds | medium | Capped at 64 candidates and 4 MiB of hashing |
| `fees::plan` could overflow; `SafeOwnsItself` was reported on v1.1.1, which allows it; GS400 was missing | low | Saturating arithmetic; defects apply per singleton version; GS400 added |
| Any four matching bytes classified a Safe as having no CREATE2 genesis | low | The call must decode |
| Flapping alerts; an unreadable balance announced "lowBalance resolved" | low | A cooldown for flapping alerts; an unreadable balance keeps a low balance raised |

## Shells (`genesis-cf`, `genesis-server`)

| Finding | Severity | Change |
| --- | --- | --- |
| About ten crafted imports (for example a zero singleton) could block the queue for good: tasks were never rotated and never failed | high | Admission mirrors the contract's preconditions; failures before a broadcast rotate the task and end it after `MAX_ERRORS` |
| Anyone could submit endless counterfactual configs, each paid for by the sponsor | high | Only Safes deployed on some chain are sponsored, within a budget (20 per minute, 500 per day); everything else gets the verified `recordCall` back to send itself |
| Resubmits used a fresh nonce, so one stuck transaction wedged the sponsor; a send that timed out was signed again at another nonce | medium | The signed transaction is stored before it is sent, then rebroadcast, then replaced at the same nonce at +25% (`submit.rs`, shared by both shells). Tested end to end on a fork with mining paused |
| A transient RPC failure was cached as a `blocked` verdict, or as a genesis with `verified: null`, for up to an hour | medium | The completeness test covers those failures; the long TTL applies only once the home chain holds the record and it re-verified; cache keys include the registry address |
| One request could fan out into thousands of RPC calls | medium | One JSON-RPC batch per chain per check; at most 64 owners; dependencies bounded by the strict shapes |
| The docker shell answered the CORS preflight with 405; the two shells returned different bodies for bad methods, bad queries and trailing slashes; the Worker returned 400 for internal errors | medium/low | A single router in the docker shell that matches the Worker's behavior; 500 for internal errors; verified side by side |
| Concurrent imports of one Safe queued twice (docker); body size was checked after reading; the in-memory cache was unbounded in bytes | low | An atomic `enqueue`; `content-length` checked first; cache entries and body sizes capped |
| The Worker re-armed its alarm before measuring it, so the "nothing scheduled" alert could never fire | info | The alarm is measured first |

## Verification after the changes

- Rust: 49 tests in `genesis-rules`, including the attack suite and all real fixtures. Clippy is clean
  on both shells, including the wasm target.
- Solidity: 17 offline tests, plus 8 fork tests on Gnosis and Base covering every sampled, known and
  user Safe:
  - about 700 replays from `genesisOf` alone;
  - no unexpected revert;
  - the only revert is a zero-owner Safe, which the test predicted;
  - the fallback handler and guard were checked after each replay.
- Both shells were run side by side on fresh forks:
  - six lookups returned identical bodies, and five HTTP edge cases returned identical status and
    body;
  - a counterfactual Safe was not sponsored;
  - the cache was hit;
  - a Lido multisig's real drift was reported: 3 of its 6 members rotated since genesis, with no
    other change to its authority;
  - same-nonce replacement worked with mining paused.
